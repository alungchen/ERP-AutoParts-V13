======================================================
     舊系統 → 新系統 單據自動同步 標準操作流程
======================================================

功能：每 5 分鐘自動把舊系統 (cck2.uparts.info) 新開的單據
同步到新系統的雲端資料庫 (Cloudflare D1)，新系統網頁即時可見。

【單號邏輯】(程式靠這個判斷哪些是新單)
  2S2607040006 = 2(汐止) + S(銷貨單) + 260704(日期) + 0006(流水號)
  第1碼：1=松山、2=汐止
  第2碼：S=銷貨、Q=報價、T=銷退、R=進退、B=進貨、I=詢價

------------------------------------------------------
👉 平常使用：啟動常駐同步 (開著就會自動跑)
------------------------------------------------------
請打開 VS Code 終端機 (Terminal)，輸入以下指令並按 Enter：

npm run sync:docs

(說明：會開啟兩個 Chrome 視窗（松山＋汐止），之後每 5 分鐘
自動檢查一輪，有新單就寫進雲端資料庫。視窗不要關，
要停止時在終端機按 Ctrl+C。)

⚠️ 第一次執行時：
  - 汐止會「自動登入」，不用理它。
  - 松山需要您在跳出的 Chrome 視窗「手動登入一次」，
    之後登入狀態會自動保存，下次就不用再登了。

------------------------------------------------------
👉 只想跑一輪測試 / 補漏
------------------------------------------------------
只跑一輪就結束：
npm run sync:docs:once

只測試不寫入資料庫（結果存 output/doc_sync_batch.sql）：
npm run sync:docs:once -- --dry-run

補同步過去幾天的單（例：從 7/1 開始往回補 5 天）：
node scripts/sync_documents_daemon.cjs --once --start=2026-07-01 --lookback=5

------------------------------------------------------
👉 常用參數 (加在指令後面，npm 指令要先加 -- )
------------------------------------------------------
--branch=xizhi        只跑汐止 (songshan=松山, both=兩店，預設 both)
--types=S,B           只監控特定單別 (預設 S,Q,T,R,B,I 六種全跑)
--interval=300        每輪間隔秒數 (預設 300 秒 = 5 分鐘)
--target=both         同時寫雲端＋本地資料庫 (預設 remote 只寫雲端)
--once                只跑一輪就結束
--dry-run             只抓取不寫入 (測試用)
--rescan              強制本次做「完整複查」(處理改單/刪單，常配 --once)
--rescan-every=12     每 N 輪自動完整複查一次 (預設 12 輪 ≈ 1 小時，0=停用)
--rescan-days=3       複查時往回重抓幾天 (預設 3 天)

範例：只跑汐止、每 3 分鐘一輪：
npm run sync:docs -- --branch=xizhi --interval=180

======================================================
💡 重要說明：
======================================================

■ 同步到哪裡？
  預設直接寫入「雲端 D1 正式資料庫」，新系統網頁馬上看得到。
  本地開發資料庫預設不寫；需要時加 --target=both，
  或事後跑 npm run db:sync:local 整包同步回本地
  （記得先停掉 dev:all，否則會出現 EPERM 錯誤）。

■ 缺料號警示（很重要！）
  如果單據裡的零件料號在新系統「產品資料庫」查不到：
  1. 該單據「備註」會加上「⚠️ 缺料號待補正: xxx」
  2. 該筆明細備註標記「⚠️ 新系統無此料號」
  3. 記錄寫入 output/doc_sync_missing.csv
  → 請定期打開這個 csv 檔，人工到新系統補建料號，
    再手動修正該單據明細。

■ 舊系統「改單」或「刪單」怎麼辦？
  平常的 5 分鐘增量輪只抓「新單號」，不會發現改單/刪單。
  所以程式每 12 輪（約 1 小時）會自動做一次「完整複查」：
  1. 改單 → 近 3 天的單整天重抓一遍，直接覆蓋新系統內容。
  2. 刪單 → 比對單號清單，新系統有但舊系統已消失的單，
     會標記為「作廢 (cancelled)」並在備註加
     「⚠️ 舊系統已刪除此單」（不會真的刪掉，保留紀錄可查）。
  想立刻處理改單/刪單，不等一小時，可手動跑：
  npm run sync:docs:once -- --rescan

■ 同步進度記在哪？
  output/doc_sync_state.json
  程式靠它記住「每個分店+單別+日期」最後同步到的流水號，
  下次只抓更新的單。刪掉此檔案 = 重新從資料庫現況重建狀態。

======================================================
💡 常見問題提醒：
======================================================
- Q: 為什麼顯示「查無單據」？
- A: 代表當天該單別在舊系統沒有開單，屬正常現象。

- Q: 為什麼顯示「需要人工登入」？
- A: 舊系統的登入過期了（ERP 會定時自動登出）。
     請到跳出的 Chrome 視窗重新登入，程式會自動繼續。

- Q: 不小心重複執行會不會造成單據重複？
- A: 不會。寫入採用 INSERT OR REPLACE，同一單號重跑
     只會覆蓋成一樣的內容，不會多出重複單據。

- Q: 電腦關機/重開後怎麼辦？
- A: 重新執行 npm run sync:docs 即可，程式會從
     doc_sync_state.json 記住的進度繼續，中間漏掉的
     當天單據會自動補齊（啟動第一輪會多查前一天補漏）。
