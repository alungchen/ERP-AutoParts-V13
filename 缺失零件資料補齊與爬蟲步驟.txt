======================================================
  舊系統 CSS2 ➔ 新系統 (erp-autoparts-v13.page.dev)
      缺失零件資料自動補齊與爬蟲操作教學指南（修正版）
======================================================

【目的與執行時機】
當您使用 `npm run sync:docs` 進行單據同步時，舊系統 (cck2.uparts.info)
開立的單據會自動同步至新系統 (erp-autoparts-v13.page.dev)。

若該單據內的零件料號 (p_id) 尚未建入新系統的「產品資料庫 (products 主檔)」，
單據顯示時只會出現「料號」，無法顯示品名、車型、品牌與照片等完整規格資訊，
且單據明細會標記「⚠️ 新系統無此料號」。

此時，執行「缺失零件資料補齊與爬蟲程序」，系統會自動：
 1. 依單據日期範圍或整體缺失資料進行比對。
 2. 找出尚未建立完整規格的料號，並打包成批次寫入 keywords.txt。
 3. 連線至舊系統爬取該料號的中文品名、車型、品牌與零件照片。
 4. 自動寫入雲端 D1 資料庫，照片自動搬家至 Cloudflare R2 雲端儲存。
 5. 自動清理單據明細中的警示標記，恢復完整頁面顯示。

※ 重要修正：
  - 此程序的完成條件不是 keywords.txt 空白，而是 D1 缺失料號查詢結果為 0。
  - 同一料號大小寫差異（例如 MAN052 / man052）會先統一做 UPPER(TRIM(...)) 比對，避免重複重抓。
  - `--month=2026-06` 是有效語法，會篩出該月單據；不是錯誤用法。

======================================================
👉 一、 操作指令範例 (請在終端機 Terminal 執行)
======================================================

1. 限定掃描特定「單一日期」的單據 (例：2026-06-09)
------------------------------------------------------
node scripts/scrape_all_missing_bg.cjs --date=2026-06-09


2. 限定掃描特定「日期區間」的單據 (例：2026年6月1日至6月30日)
------------------------------------------------------
node scripts/scrape_all_missing_bg.cjs --start-date=2026-06-01 --end-date=2026-06-30


3. 限定掃描特定「整個月」的單據 (例：2026年6整個月快捷寫法)
------------------------------------------------------
node scripts/scrape_all_missing_bg.cjs --month=2026-06


4. 全單據掃描 (不限日期，處理歷史所有單據缺失料號)
------------------------------------------------------
node scripts/scrape_all_missing_bg.cjs
(或使用 npm 快捷指令: npm run scrape:missing)


======================================================
👉 二、 正確的自動處理流程
======================================================

啟動指令後，系統會在背景按以下流程循環運作：

1. 智能比對 (prepare_missing_batch.cjs)：
   - 依指定日期條件，對 document_items 與 documents 作聯結比對。
   - 會抓出尚未建立完整產品規格的料號。
   - 會先做 `UPPER(TRIM(p_id))` 比對，避免大小寫不同卻是同一料號被重複判定為缺失。
   - 每次最多取出 30 筆，寫入 keywords.txt。

2. 背景爬蟲與雲端匯入 (run_all.cjs --headless --force)：
   - 爬蟲自動開啟無頭瀏覽器連線舊系統，抓取零件中文品名、車種年份、品牌。
   - 資料自動寫入 Cloudflare D1 正式雲端資料庫。
   - 照片自動下載並搬家上傳至 Cloudflare R2 雲端儲存桶。

3. 自動清理單據警示 (enrichDocumentItems)：
   - 每批次完成後，系統會比對新匯入的產品資料。
   - 若 `document_items.p_id` 已能對到產品主檔，會自動清理
     「⚠️ 新系統無此料號」標記，並補回品名。

4. 直到資料庫無缺失為止：
   - 程式會反覆執行上述流程，直到 D1 缺失料號查詢結果為 0。
   - 這才是實際完成，而不是 keywords.txt 直接變空，或某一批看起來已跑完。

5. 批次安全休眠：
   - 每批（30筆）執行完成後，自動休息 10 秒，避免請求過快被對方伺服器限制 IP。
   - 接著進入下一批繼續處理，直到缺失資料完全補齊。


======================================================
👉 三、 常見例外狀況與處理
======================================================

【狀況】程式中途暫停，顯示「Session Cookie 已過期（登入失效）」：
【原因】舊系統 (cck2.uparts.info) 安全機制會定期自動登出 Cookie。
【解法】
 1. 在終端機輸入： node scripts/run_all.cjs
 2. 系統會跳出 Google Chrome 視窗，請在視窗中手動登入舊系統一次。
 3. 登入成功後關閉視窗，再重新執行補齊指令，例如：
    node scripts/scrape_all_missing_bg.cjs --date=2026-06-09
 4. 程式會接續剛才的進度繼續自動抓取。


【狀況】某料號在新系統顯示「舊系統無此規格」或資料內容明顯是別的零件：
【原因】舊系統搜尋結果可能同時出現相似料號；程式已修正為只採用完全符合的搜尋詞，
        不會將相似料號誤植進產品主檔。
【解法】若發現資料有誤，可單獨重新爬取該料號：
 1. 在終端機輸入：
    node scripts/scrape_parts.cjs 【料號】 --headless --force
    範例：node scripts/scrape_parts.cjs R1-005 --headless --force
 2. 若舊系統確實不存在該料號，系統會自動標記「舊系統無此規格」作為佔位資料。
 3. 多個料號可空格分隔一起重爬：
    node scripts/scrape_parts.cjs R1-005 CLU-007-1 PM-70 --headless --force


【狀況】同一料號一直被反覆抓取：
【原因】過去曾發生大小寫差異問題，例如 MAN052 / man052 被視為不同料號，
        造成無限或長時間重複抓取。
【解法】
 1. 程式已改為使用 `UPPER(TRIM(p_id))` 做比對。
 2. 若仍出現重複，請直接檢查該料號是否已存在於 products 主檔，
    以及是否仍有 document_items 連結此料號。


======================================================
👉 四、 驗收結果
======================================================

正確的驗收不是「程式跑了一段時間」或「keywords.txt 清空」，
而是確認 D1 查詢結果為 0，表示該時間範圍內所有缺失零件料號都已補齊。

例如：
SELECT COUNT(DISTINCT di.p_id) AS count
FROM document_items di
JOIN documents d ON di.doc_id = d.doc_id
WHERE di.p_id IS NOT NULL
  AND TRIM(di.p_id) != ''
  AND d.date LIKE '2026-07%'
  AND UPPER(TRIM(di.p_id)) NOT IN (
    SELECT DISTINCT UPPER(TRIM(p_id))
    FROM products
    WHERE p_id IS NOT NULL AND TRIM(p_id) != ''
  );

若上述查詢結果為 0，表示該月份的缺失零件資料已全部補齊。

請開啟瀏覽器進入 `erp-autoparts-v13.page.dev` 網頁，重新整理頁面，
即可看到原本僅顯示料號的單據已呈現完整品名、車型與高清零件圖片。

======================================================
  補充說明：
  - 若要指定月份，請使用 `--month=YYYY-MM`。
  - 若要指定單一日期，請使用 `--date=YYYY-MM-DD`。
  - 若要指定範圍，請使用 `--start-date=YYYY-MM-DD --end-date=YYYY-MM-DD`。
  - 若不指定日期條件，則為全單據掃描。
